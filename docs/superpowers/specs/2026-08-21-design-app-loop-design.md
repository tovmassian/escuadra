# Design ↔ app iteration loop, and landing the Escuadra mark

Status: approved design, not yet planned
Date: 2026-08-21

## Problem

Two problems, one of which causes the other.

The immediate goal is to brand the app: it currently has no brand asset at all.
`assets/images/*` are stock Expo placeholders and the home screen wordmark is
the literal string `ESCUADRA` styled as an eyebrow.

The underlying problem is that the app and the Claude Design project have
drifted apart, and nothing in the current workflow pulls them back together.
The repo has moved ahead: `theme/tokens.ts` carries tokens the design side has
never seen (`errorTextDim`, `descriptionSmall`, `tableCell`), and the last five
commits are fixes discovered by running the app on a physical iPhone —
scrollable question parts, corrected per-part verdicts, early-stop on a wrong
part, pass/fail-aware results CTAs. The design project meanwhile still holds an
asset bundle built off the superseded v1 mark.

A six-screen visual re-pass driven from that stale picture would hand back
layouts that silently undo those five fixes. Preventing exactly that is the
point of this design.

## Decisions

| #   | Decision                                                        | Rationale                                                                                      |
| --- | --------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| 1   | The repo is the source of truth; the design project mirrors it  | Design starts each turn from reality, not memory                                               |
| 2   | Logo direction **2a — La Escuadra**                             | Chosen from the four v2 directions                                                             |
| 3   | Brand gradients become part of the `tokens.ts` contract         | User's call; overrides the "brand data like team colours" alternative                          |
| 4   | Add Inter 800 to `fontAssets`                                   | The wordmark needs it; the alternative was fixing the wordmark as geometry                     |
| 5   | PNG asset set is generated by Claude Design                     | It already produced one for v1; the pattern exists                                             |
| 6   | Screenshots captured with Playwright against `expo start --web` | Regenerating them is a per-turn cost, so it must be scripted                                   |
| 7   | Screen layouts sync as **prose + invariants, never as code**    | RN and HTML/CSS share no runtime; file-level screen sync produces two implementations that lie |

### Rejected

- **A design-system project with per-component HTML twins** (what `/design-sync`
  is built for). Rejected: maintaining an HTML twin of every RN component
  forever is a larger tax than the visual-diffing benefit for a six-screen
  solo v0.
- **Hand-written briefs with no mirror back** (the original rough plan).
  Rejected: nothing enforces the brief, and staleness returns immediately.

## Assumption to validate on this iteration

**Web-mobile rendering is close enough to the iPhone that design decisions made
from web screenshots transfer.** Accepted deliberately, not assumed silently:
pixel fidelity is not required and the app's layout is simple enough that large
divergence is unlikely. Known differences that will show up in the captures:

- Safe-area insets are zero on web; every screen's top and bottom padding will
  read differently than on device.
- Font hinting and rendering differ.
- `expo-haptics` is a no-op; the splash screen does not exist; AsyncStorage
  falls back to a `localStorage` shim.

This iteration is the test. If the returned re-pass proves to have been reasoned
from spacing that does not exist on device, the fallback is manual capture from
Expo Go on the phone — genuinely accurate, but not automatable.

## The sync contract

What round-trips, and in what form:

| Artifact                | Syncs as                      | Direction     |
| ----------------------- | ----------------------------- | ------------- |
| `theme/tokens.ts`       | a real file both sides import | bidirectional |
| Logo geometry (64-unit) | plain numbers                 | design → app  |
| Icon / splash rasters   | PNG exports                   | design → app  |
| Screen layouts          | prose spec + invariants       | design → app  |
| Current app state       | screenshots + token snapshot  | app → design  |

## The handoff folder

```
design/
  tokens.ts        re-export of theme/tokens.ts — one file, never a copy
  brand.ts         2a geometry + gradient stops as data
  SCREENS.md       per-screen structure, plus INVARIANTS
  screens/*.png    captured from the running app
```

`design/tokens.ts` re-exports rather than duplicates. A copy would drift, which
is the failure this whole design exists to prevent.

### `SCREENS.md` invariants

The load-bearing section. Each entry states a behaviour and why it exists, so
the design side can tell a deliberate constraint from an accident. Anything not
on the list is open for redesign.

Seeded from CLAUDE.md's hard constraints:

1. No player photographs in v0, but the question screen keeps a hero slot a
   square portrait can drop into without a redesign.
2. No club crests, badges, logos or shield shapes, ever. Clubs are identified by
   text and colour alone. National flags are **not** covered by this rule — the
   constraint's stated rationale is trademark exposure, which flags do not
   carry — and are used deliberately; see "Team identity marker" below.
3. No text input anywhere, no keyboard. Option cards and chip selectors are the
   entire input vocabulary.
4. Never hardcode a colour, spacing value or font size — everything from tokens.
   Team identity colour is content, not a token, and is exempt.
5. Every animation stays under 300ms.

And from the five recent device-driven fixes:

6. Question parts must stay scrollable — later parts became unreachable without
   it.
7. On levels 2 and 3, asking stops once a part is answered wrong.
8. Per-part verdicts show the real result; a part must never show a green check
   it did not earn.
9. No partial credit. The progress bar counts questions, not parts, so all three
   levels read 1..10.
10. Results screen CTAs differ by pass/fail and by whether the level ceiling is
    reached.

## Team identity marker

A requirement for the re-pass, not an invariant — invariants preserve existing
behaviour, and this is new.

Today `components/TeamRow.tsx` renders a single flat dot filled with
`primaryColor`. `secondaryColor` is present on every squad and in
`data/index.json` and is **rendered nowhere**. The marker should carry more
identity than one flat colour, and should differ by `squad.kind`:

- **Clubs** keep colour as the identifier, but use both colours where the club
  genuinely has two — Barcelona `#A50044/#004D98`, Inter `#0068A8/#000000`,
  PSG `#004170/#DA291C`, Juventus if added. Split dot, halved or diagonal; the
  design side picks the treatment. Still no emblems, per invariant 2. This needs
  **no new data** — both fields already exist and are already correct.
- **Nations** get their flag, and the marker may be larger than the current dot
  to make a flag legible.

### Flags need their own data field

The existing colour fields are **kit colours, not flag colours**. Japan is
`#000B8C` (the blue kit) against a white-and-red flag; Armenia is
`#B70000/#FFFFFF` against a red/blue/orange tricolour. Deriving flags from
`primaryColor`/`secondaryColor` would render roughly half the nations wrong.

So a `flag` field is added to nation squads and to `data/index.json` (the picker
never imports full squad JSON, so both carry it, exactly as the colour fields
already do). It is declarative geometry, not an asset:

```
flag?: { bands: string[]; orientation: 'horizontal' | 'vertical';
         overlay?: { shape: 'disc' | 'diamond'; color: string } }
```

That covers every nation currently in the repo: France and Armenia as bands,
Spain as bands, Japan as a white field with a red disc, Brazil as a green field
with a yellow diamond, Argentina as bands. National emblems and coats of arms
are omitted — Spain without its arms is the civil flag, Argentina without the
sun and Brazil without the celestial globe remain unambiguous at this size, and
omitting them keeps the marker consistent with the app's geometric language.

### Why not emoji flags

The cheap option is the Unicode regional-indicator flag (🇦🇷), and it is
rejected for a concrete reason: it depends on an OS flag-emoji font. **Windows
has none.** The Playwright captures in this very loop run against Chrome on
Windows, so design would receive screenshots showing the letter pair `AR`
instead of a flag — the new requirement would break the loop on its first
iteration. Declarative geometry renders identically on web and on iOS, which is
what the app→design direction depends on.

### Consequences

- `types/squad.ts`, `data/index.json` and the six nation squad files change.
  This is Turn 0 work, because design needs the flag data to design against.
- The `squad-updater` skill must learn to populate `flag` when adding a nation.
- Flag values should be **hand-checked**, not accepted from generation. Unlike
  shirt numbers they are small in number, stable, and trivially verifiable, so
  the `verified: false` caveat need not extend to them.

## The 2a mark

Geometry, `viewBox 0 0 64 64`:

- crossbar: `rect x=14 y=10 w=40 h=10`
- post: `rect x=44 y=10 w=10 h=40`
- ball: `circle cx=35 cy=31 r=9`
- trail (full lockup only, dropped in icon plates):
  `rect x=16 y=44 w=7 h=7` at 0.55 opacity, `rect x=5 y=53 w=5 h=5` at 0.3

Because the mark is entirely axis-aligned rectangles plus one circle, it renders
in plain React Native `<View>`s with `borderRadius`. No `react-native-svg`, no
Metro SVG transformer. (2c's hollow triangle would have forced that dependency.)

The ball does not overlap either bar — a two-unit gap to the crossbar, tangent
to the post — so the silhouette stays clean in a single colour. The monochrome
Android layer must render the ball at full opacity rather than the 0.85 used on
the coloured plates.

### New colour values entering tokens

`#5b63d6`, `#2f3585`, `#8f97ea`, `#6d76e6`, and two gradients (`esgrad`,
`esgradSoft`). Per decision 3 these join `theme/tokens.ts`.

Consequence: RN `<View>` cannot render a gradient, so a gradient token is
declarative data with nowhere to land. `expo-linear-gradient` must be added
along with a small renderer. It ships inside Expo Go, so the Expo Go constraint
holds — to be verified at install, not assumed.

## Turn protocol

**Turn 0 — repo.** Build `design/`. Add gradient tokens and Inter 800.
Transcribe 2a into `brand.ts`. Add the `flag` field to the nation squads and the
manifest. Add Playwright and an `npm run shots` script.
Capture the app as it stands today, unbranded.

**Turn 1 — design.** Push `design/` to the Claude Design project via
`DesignSync`. Ask for three deliverables: the PNG asset set, the wordmark
lockups, and the six-screen re-pass.

**Turn 2 — repo.** Apply the assets first, so branding lands as its own commit.
Then apply screen deltas one screen per commit, each checked against the
invariants.

**Turn 3+.** Re-capture screenshots, push back, repeat.

### Plan boundary

The implementation plan that follows this spec covers **Turn 0 only**. Turn 1 is
an action on the design side, and Turn 2 cannot be planned before Turn 1's
output exists — planning against imagined deliverables would be guesswork. Turn
2 gets its own plan once the assets and the re-pass are actually in hand.

## Known frictions

- **The results screen cannot be reached by URL.** `stores/session.ts` is
  deliberately ephemeral, so the capture script has to actually play a round to
  get there.
- **No `testID`s exist** on the components. The script leans on text selectors
  until they are added.
- **`npm start` is `expo start --tunnel`.** Web capture needs a separate
  non-tunnelled web target. _(Resolved 2026-09-06: `npm start` dropped
  `--tunnel` — plain Wi-Fi connects on SDK 57. Web capture still spawns its own
  `--web` target, so the script is unaffected.)_
- **The design project is `PROJECT_TYPE_PROJECT`, not a design system.** Read
  access is confirmed working; write access via `finalize_plan` → `write_files`
  is unverified against a project of this type.
- **The existing `uploads/Escuadra Design/assets/` bundle is stale** — v1
  geometry, and its wordmark is a light-background lockup (`fill="#0f1115"`)
  drawn with live `<text>` in Inter, which will not survive on a surface without
  Inter installed. It must be regenerated, not adapted.

## Out of scope

Everything CLAUDE.md defers for v0 stays deferred: store distribution, player
photos, monetisation, auth, any network call, multiplayer, leaderboards, Exam
mode. This design adds no exception to that list.
