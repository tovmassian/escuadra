# #112 — 960 px photos and the original's size: Implementation Plan

**Issue:** [#112](https://github.com/tovmassian/escuadra/issues/112) · **Milestone:** [v2.0.0](https://github.com/tovmassian/escuadra/milestone/5) · **Branch:** `feat/112-photo-960`

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every stored player photo is a 960 px Commons thumbnail (or the original, when Commons serves one no wider unscaled), and carries its original's `width` and `height`.

**Architecture:**

- `squadctl enrich` already rewrites every photo on each run. It asks Commons for each file's thumbnail, page and credit metadata in one `imageinfo` query (`CREDITS` in `tools/squadctl/src/lib/photo-credit.ts`).
- This plan raises the requested width to 960, adds `size` to `iiprop` so Commons returns the original's dimensions, and makes them part of `PhotoCredit`. A file with no size is refused like any other incomplete credit.
- The enrich cache is keyed by query shape, so the changed query refetches. A live run then rewrites `data/players.json`.
- The app reads only `photo.url` today. Issue #113 will read `width` and `height` to frame small originals (spec §2.6).

**Tech Stack:** TypeScript on Node 24 (native type stripping, no build), oclif (`squadctl`), Vitest.

**Spec:** [`docs/superpowers/specs/2026-10-15-play-redesign-2-0-design.md`](../specs/2026-10-15-play-redesign-2-0-design.md) §9 (resolution), §12 (CLAUDE.md data model), §13 (data tests), §14 item 2.

## Global Constraints

- Node 24: run `nvm use` in every new shell before any `npm` or `node` command.
- **`squadctl enrich` is the only writer of `player.photo`** (CLAUDE.md guardrail 1). Never hand-edit `data/players.json`.
- **The licence rules do not change:**
  - which licences are accepted (`isAcceptedLicence`, `isAttributionOnly`, `MAX_CREDIT_NAME`)
  - what a credit must carry
  - the Commons-page rule
- **Network:** only Task 1 Step 6 (the fixture re-recording, one request) and Task 2 Step 3 (the live `enrich`) touch Wikimedia. Both send squadctl's `DEFAULT_USER_AGENT`.
- **No new dependency or npm script, and no `app.json` change.**
- **Tests stay beside the code:**
  - `tools/squadctl/src/**/*.test.ts`
  - `tools/squadctl/src/lib/__fixtures__/`
  - `lib/*.test.ts`
- **Squad files and `verified` flags are untouched.** Enrich writes only `data/players.json`.
- **Before each commit,** run `npx prettier --write <every file you changed>`. The full `npm run check` runs at pre-push.
- **Never write to /tmp.** Scratch files go in the SDD workspace directory the controller names.
- Each commit ends with a `Co-Authored-By` trailer naming the model that wrote it.
